# دروازهٔ هوش مصنوعی و GPT-Live هکتور (Cloudflare Worker)

این Worker کلید اصلی OpenAI را سمت سرور نگه می‌دارد. در نسخهٔ فعلی APK، صفحهٔ امن WebView هکتور به مسیر /live همین Worker متصل می‌شود؛ کلید اصلی OpenAI داخل APK لازم نیست.

## راه‌اندازی با گوشی اندروید

1. وارد https://dash.cloudflare.com/ شو و بخش Workers & Pages را باز کن.
2. Worker با نام hector-ai-gateway بساز.
3. محتوای فایل src/index.js را در ویرایشگر Worker قرار بده و Deploy کن.
4. در Settings → Variables and Secrets دو Secret بساز:
   - OPENAI_API_KEY = کلید API OpenAI
   - HECTOR_GATE_TOKEN = یک رمز طولانی و تصادفی که خودت انتخاب می‌کنی. آن را در GitHub یا گفت‌وگو منتشر نکن.
5. اختیاری: متغیر OPENAI_MODEL را برای مسیر متنی تنظیم کن؛ پیش‌فرض gpt-4.1-mini است.
6. در هکتور، «تنظیم اتصال هوش مصنوعی» را باز کن و نشانی کامل https://YOUR-WORKER.workers.dev/live را در فیلد «دروازهٔ GPT-Live» ذخیره کن. باید HTTPS و دقیقاً مسیر /live داشته باشد؛ بدون query یا fragment.
7. از خانه «گفت‌وگوی زنده GPT-Live» را بزن. صفحهٔ Worker در WebView امن باز می‌شود؛ رمز HECTOR_GATE_TOKEN را در همان صفحه وارد کن و شروع مکالمه را بزن. مجوز میکروفون را فقط اگر می‌خواهی مکالمه را آغاز کنی بده.
8. برای پایان مکالمه از دکمهٔ پایان صفحه یا اعلان دائمی «پایان صدا» استفاده کن. «توقف اضطراری HIC-STOP-01» در صفحهٔ صوتی نیز مکالمه را متوقف و وضعیت توقف را ذخیره می‌کند.

## مسیر متنی اختیاری

مسیر /chat نیز به همان رمز محرمانهٔ HECTOR_GATE_TOKEN نیاز دارد؛ درخواست بدون سرآیند مجاز با پاسخ 401 رد می‌شود. نمونهٔ درخواست:

```sh
curl -X POST 'https://YOUR-WORKER.workers.dev/chat' \
  -H 'Authorization: Bearer YOUR_HECTOR_GATE_TOKEN' \
  -H 'Content-Type: application/json' \
  --data '{"message":"سلام، خودت را معرفی کن"}'
```

جایگزین YOUR_HECTOR_GATE_TOKEN را فقط در محیط امن خودت انجام بده؛ رمز واقعی را در مخزن، گفتگو یا لاگ‌ها قرار نده.

## امنیت و محدودیت‌ها

- هرگز کلید اصلی OpenAI را در APK، گفتگو یا فایل‌های مخزن قرار نده؛ این مسیر از Secret سمت سرور استفاده می‌کند.
- رمز HECTOR_GATE_TOKEN محرمانه است؛ اگر افشا شد، آن را در Cloudflare عوض کن.
- WebView فقط HTTPS و مبدأ/مسیر پیکربندی‌شده را می‌پذیرد، دسترسی فایل و محتوای محلی غیرفعال است و فقط مجوز میکروفون درخواست می‌شود.
- اعلان دائمی سرویس صوتی هنگام استفاده از GPT-Live باقی می‌ماند؛ گزینهٔ «پایان صدا» باید جریان صوتی WebView را هم متوقف کند. دکمهٔ توقف اضطراری در خود صفحه وضعیت توقف را ذخیره می‌کند.
- محدودسازی درخواست در این نمونه ابتدایی است و ممکن است در شرایط هم‌زمانی یا چند منطقه‌ای سقف دقیقی تضمین نکند. پیش از استفادهٔ عمومی، احراز هویت قوی‌تر، محدودیت هزینه و rate limiting پایدار اضافه کن.
- GPT-Live به دسترسی API و پرداخت/اعتبار API جدا از اشتراک ChatGPT نیاز دارد. ایجاد نشست و مدت مکالمه می‌تواند هزینه داشته باشد.
- تغییر کد در مخزن به معنی انتشار Worker، ساخت APK جدید یا آزمون موفق روی گوشی نیست؛ این موارد باید جداگانه تأیید شوند.


## صف کار ابری پایدار (MVP آزمایشی)

این نسخه یک صف محدود برای **درخواست‌های متنی مدل** اضافه می‌کند؛ هنوز ابزار مرور وب، اجرای فرمان، دسترسی به فایل‌های گوشی یا اجرای خودکار اقدام‌های خارجی نیست.

### تنظیمات سمت سرور

1. در Cloudflare، Worker را از روی همین پوشه و فایل `wrangler.toml` منتشر کن تا binding و migration مربوط به Durable Object ساخته شود.
2. Secretهای موجود `OPENAI_API_KEY` و `HECTOR_GATE_TOKEN` را برای مسیرهای قدیمی `/chat` و `/live/session` حفظ کن. کلید اصلی ارائه‌دهنده را هرگز داخل APK نگذار.
3. مقدار غیرمحرمانهٔ `FIREBASE_PROJECT_ID` باید با پروژهٔ Firebase برنامه برابر باشد؛ این مخزن آن را `hector-9b819` تنظیم کرده است.
4. پیش از انتشار عمومی، تست‌های Worker را با `npm test` در پوشهٔ `cloudflare-worker` اجرا کن. سپس Deploy واقعی را جداگانه انجام بده؛ اجرای تست به معنی انتشار نیست.

### API صف

- `POST /tasks` با سرآیند `Authorization: Bearer <Firebase ID token>` و بدنهٔ `{"prompt":"درخواست متنی","idempotencyKey":"شناسه-اختیاری"}` یک کار صف‌شده ایجاد می‌کند.
- `GET /tasks/<task-id>` با Firebase ID token همان حساب وضعیت و نتیجه را برمی‌گرداند.
- هر شناسهٔ Firebase به صف Durable Object جداگانه نگاشت می‌شود؛ حساب دیگر نمی‌تواند با همان API به صف آن حساب دسترسی پیدا کند.
- هر درخواست حداکثر ۴۰۰۰ نویسه است، حداکثر ۲۰ کار در انتظار مجاز است و تاریخچهٔ ذخیره‌شده برای هر حساب محدود می‌شود. کارها در صورت خطای موقت یک بار دوباره تلاش می‌شوند.
- وضعیت‌ها: `queued`, `processing`, `completed`, `failed`. متن درخواست در فضای ذخیره‌سازی صف باقی می‌ماند تا کار پردازش شود یا رکورد قدیمی پاک شود؛ اطلاعات حساس را در prompt قرار نده.

### محدودیت مهم

این تغییر فقط **سمت سرور** است. نسخهٔ فعلی Android هنوز به این API وصل نشده؛ اتصال کلاینت باید جداگانه از FirebaseAuth توکن ID بگیرد، کار را ثبت کند، وضعیت را همگام کند و نتایج را امن نمایش دهد. تا آن مرحله، این API را قابلیت آمادهٔ استفاده در برنامه تلقی نکن. همچنین وقتی گوشی کاملاً آفلاین است، نمی‌تواند درخواست تازه‌ای به ابر بفرستد؛ صف ابری فقط کارهایی را انجام می‌دهد که قبلاً دریافت کرده و نتیجه را برای اتصال بعدی نگه می‌دارد.
