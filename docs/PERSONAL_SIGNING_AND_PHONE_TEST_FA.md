# امضای ثابت شخصی و آزمون واقعی روی گوشی هیکتور

هدف: نصب خصوصی هیکتور روی گوشی خودمان؛ بدون انتشار در Google Play.

## ۱) کلید امضای ثابت

- برای اینکه نسخه‌های بعدی به‌عنوان به‌روزرسانی روی نصب فعلی بنشینند، همه نسخه‌ها باید با همان گواهی امضا شوند.
- فایل ~/.android/debug.keystore که GitHub Actions می‌سازد یا از cache برمی‌گرداند، فقط برای تشخیص و آزمایش است. Cache ممکن است حذف شود؛ بنابراین به آن به‌عنوان نگهداری دائمی کلید تکیه نکن.
- برای امضای پایدار، یک keystore شخصی بساز و چند نسخه پشتیبان رمزگذاری‌شده و آفلاین از آن نگه دار. فایل keystore و رمزها را در مخزن، issue، چت یا فایل APK قرار نده.
- کلید انتشار را فقط در GitHub Actions Secrets مخزن خصوصی ثبت کن. چهار secret مورد انتظار workflow:
  - HECTOR_RELEASE_KEYSTORE_BASE64: محتوای Base64 فایل keystore شخصی
  - HECTOR_RELEASE_STORE_PASSWORD: رمز keystore
  - HECTOR_RELEASE_KEY_ALIAS: alias دقیق کلید
  - HECTOR_RELEASE_KEY_PASSWORD: رمز کلید
- رمزها و keystore باید با یکدیگر تطبیق داشته باشند. تا وقتی این چهار مورد واقعی تنظیم و ساخت Release موفق نشده، APK را «امضای انتشار پایدار» ننام.
- کلید API هوش مصنوعی مستقل از کلید امضای APK است؛ این دو را جایگزین هم نکن.

## ۲) بررسی ساخت در GitHub Actions

برای آخرین اجرای workflow:
1. وضعیت نهایی باید Success باشد و مراحل Android Lint، آزمون‌های JVM، ساخت APK و بررسی امضا موفق باشند.
2. فایل APK و فایل signing-certificate.txt را از artifact همان اجرا دریافت کن، اگر artifact در دسترس است.
3. fingerprint گواهی و SHA-256 را برای همان APK ثبت کن.
4. قبل از نصب به‌روزرسانی، fingerprint گواهی APK جدید را با نسخه نصب‌شده مقایسه کن. گواهی متفاوت یعنی ممکن است به‌روزرسانی رد شود.
5. APK تشخیصی debug و APK امضاشده با کلید شخصی دو نوع متفاوت‌اند؛ بین آن‌ها رفت‌وبرگشت نکن، مگر آنکه نصب تمیز را آگاهانه انتخاب کرده باشی و داده‌های محلی را از دست‌دادنی بدانی.

## ۳) آزمون واقعی روی گوشی

این موارد فقط پس از نصب روی دستگاه قابل تأییدند؛ CI نمی‌تواند به‌جای گوشی واقعی این آزمون‌ها را انجام دهد.

- [ ] نصب فایل کامل می‌شود و اندروید خطای امضا یا ناسازگاری بسته نشان نمی‌دهد.
- [ ] برنامه باز می‌شود و مستقیماً صفحه اصلی را نشان می‌دهد؛ هیچ ورود اثر انگشت، چهره، صدا یا رمز نمی‌خواهد.
- [ ] کلید توقف اضطراری HIC-STOP-01 قابل فعال‌کردن است.
- [ ] پس از بستن و بازکردن برنامه، وضعیت توقف حفظ می‌شود؛ آزادکردن آن فقط با اقدام صریح کاربر انجام می‌شود.
- [ ] بدون اجازه میکروفن، قابلیت صوتی شروع به ضبط نمی‌کند؛ مجوز فقط در زمان نیاز درخواست می‌شود.
- [ ] با قطع اینترنت، برنامه از کار نمی‌افتد و خطای قابل فهم نشان می‌دهد.
- [ ] اگر API تنظیم نشده، برنامه ادعا نمی‌کند که به هوش مصنوعی متصل است.
- [ ] کلید API در صفحه، گزارش‌ها یا پیام خطا افشا نمی‌شود.
- [ ] پس از راه‌اندازی مجدد گوشی، برنامه دوباره باز می‌شود و داده‌های امن قابل‌خواندن/خراب‌شدن غیرمنتظره ندارند.

برای هر مورد نتیجه «قبول/رد» و متن خطا را ثبت کن. اگر نصب هشدار امنیتی می‌دهد، هشدار را کورکورانه خاموش نکن؛ نام دقیق هشدار و منبع APK را بررسی کن.

## ۴) نتیجه‌گیری

ساخت موفق و امضای معتبر، به‌تنهایی اثبات‌کننده امنیت کامل یا کارکرد صحیح روی گوشی نیست. وضعیت نهایی فقط وقتی تأیید می‌شود که ساخت موفق باشد، گواهی مورد انتظار تأیید شود و آزمون‌های واقعی روی دستگاه ثبت شوند.
