# چک‌لیست نصب، مجوزها و انتشار هیکتور

این سند وضعیت فنی مخزن را از تأییدیه‌های بیرونی جدا می‌کند. وجود یک مورد در این چک‌لیست به‌تنهایی به معنی گذراندن آزمایش یا دریافت تأییدیه نیست.

## وضعیت فعلی پروژه در مخزن

- شناسهٔ برنامه: `com.hector.android`
- نسخهٔ ثبت‌شده در Gradle: `1.5.1-stop-only`، کد نسخهٔ 25
- حداقل Android API: 23
- `compileSdk` و `targetSdk`: 36 (Android 16)
- ورود: بدون اثر انگشت، چهره، تشخیص زنده‌بودن، تشخیص هویت صوتی یا رمز ورود؛ برنامه مستقیم باز می‌شود.
- توقف اضطراری: `HIC-STOP-01`؛ این کلید، احراز هویت کاربر یا قفل امنیتی دستگاه نیست.
- ساخت CI: آزمون‌های JVM، بررسی‌های ثابت، ساخت APK آزمایشی و بررسی امضای APK تعریف شده‌اند. موفقیت اجرای واقعی این مراحل باید از نتیجهٔ GitHub Actions تأیید شود.

## مجوزهای اندروید

در `app/src/main/AndroidManifest.xml` فقط این مجوزهای برنامه ثبت شده‌اند:

- `INTERNET`: برای اتصال اختیاری به سرویس هوش مصنوعی؛ مجوز زمان اجرا نمی‌خواهد.
- `RECORD_AUDIO`: برای ورودی گفتار و گفت‌وگوی زنده؛ باید هنگام استفاده از قابلیت میکروفون از کاربر درخواست شود. اگر رد شود، بخش متنی برنامه باید همچنان قابل استفاده بماند.

برنامه در حال حاضر مجوز دوربین، مکان، مخاطبین، پیامک، تماس تلفنی یا دسترسی عمومی به فایل‌های گوشی درخواست نمی‌کند. این مجوزها را صرفاً برای «کامل‌تر شدن» اضافه نکنید؛ فقط در صورت نیاز واقعی و همراه با توضیح و آزمون مناسب اضافه شوند.

## پیش از نصب مستقیم APK روی گوشی

- [ ] نتیجهٔ آخرین اجرای GitHub Actions بررسی شود؛ ساخت موفق را از روی وجود فایل workflow فرض نکنید.
- [ ] APK با گواهی دیجیتال معتبر امضا شده باشد.
- [ ] شناسهٔ بسته و گواهی امضای نسخهٔ به‌روزرسانی با نسخهٔ نصب‌شده سازگار باشند؛ در غیر این صورت نصب به‌روزرسانی ممکن است رد شود.
- [ ] فایل فقط از مخزن/مسیر انتشار مورد اعتماد دریافت شود و هش SHA-256 فایل ثبت یا مقایسه شود.
- [ ] در Android، اجازهٔ نصب از همین منبع فقط در صورت نیاز و با انتخاب خود کاربر فعال شود؛ پس از نصب می‌توان آن را دوباره غیرفعال کرد.
- [ ] در اولین اجرا، صفحهٔ اصلی بدون درخواست ورود اضافی باز شود.
- [ ] قابلیت متنی بدون مجوز میکروفون کار کند؛ با رد مجوز میکروفون، برنامه از کار نیفتد.
- [ ] توقف اضطراری، ذخیره و بازیابی حافظه، قطع شبکه، رفتن به پس‌زمینه و بازگشت به برنامه آزمایش شوند.
- [ ] نصب تازه و به‌روزرسانی روی گوشی هدف آزمایش شود. موفقیت CI به‌تنهایی سازگاری با همهٔ گوشی‌ها را اثبات نمی‌کند.

## پیش از انتشار عمومی یا انتشار در Google Play

- [ ] کلید امضای انتشار و رمزهای آن امن و پشتیبان‌گیری شده باشند؛ کلید خصوصی و رمزها هرگز داخل مخزن ثبت نشوند.
- [ ] اگر انتشار رسمی لازم است، نسخهٔ release امضا شود؛ APK آزمایشی debug به‌عنوان نسخهٔ رسمی معرفی نشود.
- [ ] سیاست حریم خصوصی قابل دسترس و دقیق آماده شود؛ نحوهٔ نگهداری یادداشت‌ها/تاریخچه و ارسال محتوای گفتگو به endpoint انتخابی کاربر توضیح داده شود.
- [ ] فرم Data safety و اعلام‌های مربوط به داده‌ها در Play Console، در صورت انتشار در Google Play، بر اساس رفتار واقعی برنامه تکمیل شوند.
- [ ] اطلاعات صفحهٔ فروشگاه، آیکون، تصاویر، رده‌بندی محتوا و اطلاعات تماس پشتیبانی آماده شوند.
- [ ] الزامات حساب توسعه‌دهنده، آزمایش اجباری/دورهٔ آزمایشی و بازبینی Play Console برای نوع حساب و منطقه بررسی شوند.
- [ ] نسخهٔ هدف API و سیاست‌های جاری Google Play درست پیش از ارسال دوباره بررسی شوند. در تاریخ این سند، برای برنامه‌های جدید و به‌روزرسانی‌های عادی Google Play از ۳۱ اوت ۲۰۲۶، API 36 یا بالاتر لازم است؛ مخزن فعلی API 36 را هدف می‌گیرد.
- [ ] فقط پس از اجرای واقعی آزمایش‌ها، نتایج با وضعیت «موفق» ثبت شوند.

## مواردی که مخزن به‌تنهایی نمی‌تواند تأیید کند

این موارد به حساب‌ها، کلیدها، دستگاه واقعی یا تصمیم سرویس بیرونی وابسته‌اند: تأیید Google Play، تکمیل هویت حساب توسعه‌دهنده، امضای نهایی با کلید خصوصی، نصب موفق روی گوشی مشخص، در دسترس بودن endpoint و اعتبار کلید API. این سند هیچ‌یک از آن‌ها را به‌عنوان تأییدیهٔ دریافت‌شده اعلام نمی‌کند.
