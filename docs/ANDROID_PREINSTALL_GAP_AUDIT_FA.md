# ممیزی شکاف‌های پیش از نصب هیکتور (فارسی)

تاریخ ممیزی: 2026-10-19  
شاخه بررسی‌شده: `@Chat-GPT`  
شناسه بسته: `com.hector.android`  
هدف توزیع: نصب خصوصی روی دستگاه‌های خودمان؛ نه انتشار در Google Play.

این سند چک‌لیست عملی برای بررسی پیش از نصب است؛ وجود این سند یا موفقیت CI به‌تنهایی به معنی تأیید رسمی اندروید، بی‌خطا بودن برنامه یا موفقیت نصب روی گوشی نیست.

## نتیجه اولیه

در مخزن مواردی مانند گردش‌کار ساخت، آزمون‌های JVM، Android Lint، بررسی امضای APK، راهنمای نصب خصوصی، `allowBackup=false`، جلوگیری از ترافیک HTTP ساده، ذخیره امن با Android Keystore، و کلید توقف `HIC-STOP-01` وجود دارد. در Manifest فعلی فقط مجوز اینترنت و میکروفن تعریف شده‌اند؛ قابلیت میکروفن برای نصب روی دستگاه‌های فاقد میکروفن اجباری نیست. مجوزهای اثر انگشت، دوربین و مجوزهای اختصاصی Google Play Services عمداً وجود ندارند.

موارد زیر باید در اجرای واقعی تأیید شوند:
- تمام مراحل CI روی آخرین commit موفق باشند و artifact واقعاً ساخته شود.
- فایل APK دانلودشده کامل باشد، اندازه و SHA-256 آن ثبت شود و امضایش با `apksigner verify` معتبر باشد.
- گواهی امضای APK نسخه نصب‌شده و نسخه جدید یکسان باشد؛ در غیر این صورت Android ممکن است به‌روزرسانی را رد کند. برای نصب تمیز، نسخه قبلی فقط پس از اطمینان از پشتیبان‌گیری اطلاعات لازم حذف شود.
- نسخه نصب‌شده روی Android 14 و حداقل نسخه پشتیبانی‌شده آزمایش شود؛ نصب موفق روی یک دستگاه تضمین سازگاری همه دستگاه‌ها نیست.
- برنامه بعد از بازشدن مستقیماً صفحه اصلی را نشان دهد، درخواست ورود زیست‌سنجی/رمز نکند، و کلید توقف را بتوان روشن کرد، پس از بستن و بازکردن برنامه وضعیت آن باقی بماند و آزادسازی توقف فقط با اقدام صریح کاربر انجام شود.
- مسیرهای شبکه، پاسخ خطا، قطع اینترنت، لغو درخواست، و عدم نمایش کلید API در گزارش‌ها یا رابط کاربری بررسی شوند.
- مجوزهای زمان اجرا فقط هنگام نیاز واقعی درخواست شوند. `RECORD_AUDIO` برای قابلیت صوتی است؛ اگر کاربر صوت را فعال نکند، برنامه نباید بی‌دلیل میکروفن را به کار گیرد.
- در خروجی APK، Manifest ادغام‌شده و مجوزهای وابستگی‌ها بررسی شوند؛ Manifest منبع ممکن است تمام مجوزهای افزوده‌شده توسط کتابخانه‌ها را نشان ندهد.

## مواردی که عمداً نباید اضافه شوند

برای نصب خصوصی، افزودن مجوزهای بی‌نیاز مثل مخاطبین، پیامک، موقعیت مکانی، دوربین یا دسترسی گسترده به فایل‌ها لازم نیست. این مجوزها را فقط در صورت نیاز واقعی و با آزمون و توضیح روشن اضافه کنید. هشدار امنیتی اندروید یا Play Protect را کورکورانه خاموش نکنید.

## مسیر امن نصب خصوصی

1. فقط artifact مربوط به اجرای موفق GitHub Actions را از مخزن خصوصی دریافت کنید.
2. اگر APK از طریق مرورگر یا Files by Google نصب می‌شود، در صورت درخواست اندروید فقط اجازه «نصب برنامه‌های ناشناس» را برای همان برنامه نصب‌کننده و فقط در زمان لازم فعال کنید.
3. اگر هشدار امنیتی ظاهر شد، نام دقیق هشدار و منبع فایل را بررسی کنید؛ هشدار را نادیده نگیرید.
4. اگر دانلود روی ۱٪ می‌ماند، آن را نشانه ساخته‌شدن فایل ندانید؛ ابتدا در GitHub Actions وجود artifact و پایان موفق job را بررسی کنید.
5. پس از نصب، نسخه برنامه، بازشدن صفحه اصلی، عملکرد توقف اضطراری، مجوز میکروفن، قطع اینترنت و رفتار پس از راه‌اندازی مجدد را آزمایش کنید.

## امضا و نسخه انتشار

- APK نصب‌پذیر باید امضای دیجیتال معتبر داشته باشد.
- APK تشخیصی debug برای آزمایش است و نباید به‌عنوان نسخه انتشار رسمی معرفی شود. در صورت پر بودن سهمیه Artifact، فایل تشخیصی از طریق Pre-release خصوصی در GitHub Releases منتشر می‌شود؛ این fallback به معنی انتشار نسخه رسمی نیست.
- برای انتشار پایدار، کلید انتشار خصوصی را خارج از مخزن نگه دارید و فقط از GitHub Actions Secrets استفاده کنید. فایل keystore، رمزها یا کلید API را commit نکنید.
- همان کلید انتشار را به‌طور امن نگه دارید؛ تغییر کلید می‌تواند به‌روزرسانی نصب موجود را مختل کند.
- پس از هر انتشار، SHA-256 فایل، fingerprint گواهی، شماره نسخه و commit سازنده را ثبت کنید.
- برای هر تغییری که از اینترنت می‌آید، HTTPS، اعتبارسنجی URL و رفتار redirect باید بررسی شود؛ certificate pinning فقط پس از طراحی و برنامه نگهداری درست اضافه شود، نه به‌صورت عجولانه.

## تأیید توسعه‌دهنده اندروید

تأیید هویت توسعه‌دهنده با ساخت و امضای APK یکی نیست. در 2026-10-19، راهنمای رسمی Android می‌گوید محدودیت‌های تأیید از 30 سپتامبر 2026 در مناطق و فروشگاه‌های مشخص آغاز شده و گسترش جهانی برای 2027 برنامه‌ریزی شده است. برای توزیع صرفاً خارج از Google Play، مسیر Android Developer Console را بررسی کنید؛ ثبت هویت یا بسته تنها وقتی انجام‌شده محسوب می‌شود که خود کنسول آن را تأیید کند.

## راهنمای امضای شخصی و آزمون گوشی

راهنمای تکمیلی امضای ثابت و آزمون دستگاه در [PERSONAL_SIGNING_AND_PHONE_TEST_FA.md](PERSONAL_SIGNING_AND_PHONE_TEST_FA.md) ثبت شده است. فایل debug.keystore در cache گردش‌کار فقط برای آزمون است؛ چون cache ممکن است حذف شود، جایگزین نگهداری امن یک کلید امضای شخصی نیست. گردش‌کار اکنون fingerprint گواهی debug و فایل SHA-256 را نیز همراه APK در artifact قرار می‌دهد، تا دریافت‌کننده بتواند فایل همان اجرا را بررسی کند.

## معیار تکمیل

این ممیزی فقط وقتی «تأییدشده» علامت می‌خورد که:
- [ ] آخرین اجرای CI موفق باشد.
- [ ] artifact APK وجود داشته باشد و قابل دریافت باشد.
- [ ] امضا و fingerprint بررسی شده باشند.
- [ ] نصب و بازشدن واقعی روی گوشی هدف موفق باشد.
- [ ] آزمون‌های اصلی صفحه اصلی، مجوزها، شبکه، ذخیره‌سازی امن و توقف اضطراری ثبت شده باشند.
- [ ] هشدار نصب، اگر وجود دارد، با دلیل مشخص و مستند حل شده باشد.
