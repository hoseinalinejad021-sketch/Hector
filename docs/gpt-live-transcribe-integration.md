# GPT-Live-Transcribe برای هیکتور

## هدف
مدل `gpt-live-transcribe` گفتار زنده را با تأخیر کم به متن تبدیل می‌کند. این مدل خودش پاسخ صوتی تولید نمی‌کند، ابزار اجرا نمی‌کند و هویت گوینده را تأیید نمی‌کند.

## پیکربندی پیشنهادی
- استفاده از Realtime Transcription API، نه Chat Completions برای جریان زنده.
- نوع نشست: `transcription`
- مدل: `gpt-live-transcribe`
- ورودی صوت: PCM16 با نرخ 24,000 هرتز، مطابق پیکربندی کلاینت.
- برای گفتار فارسی، آزمایش با `languages: ["fa"]`؛ اگر API در نشست مورد استفاده این کد زبان را نپذیرد، خطا را ثبت و تنظیم را اصلاح کنید.
- برای کاهش تأخیر، آزمایش با `delay: "low"`؛ کیفیت را با صدای واقعی، لهجه‌ها و نویز پس‌زمینه بسنجید.
- این مدل از `server_vad` و `semantic_vad` در این نوع نشست پشتیبانی نمی‌کند؛ پایان گفتار را در کلاینت تشخیص دهید و سپس `input_audio_buffer.commit` بفرستید.
- متن‌های موقت ممکن است اصلاح شوند؛ متن نهایی را با `item_id` به نوبت صوتی مربوط وصل کنید.

## جریان لازم برای پیاده‌سازی
1. برنامه مجوز میکروفون را از کاربر بگیرد و فقط هنگام اقدام آگاهانه کاربر ضبط را شروع کند.
2. سرور مورد اعتماد، نشست را ایجاد و اعتبارنامه کوتاه‌عمر کلاینت را برگرداند؛ کلید اصلی API هرگز داخل APK، مخزن یا لاگ قرار نگیرد.
3. برنامه از WebRTC یا WebSocket پشتیبانی‌شده استفاده کند و قطعه‌های صوت را با رویداد `input_audio_buffer.append` ارسال کند.
4. برنامه رویدادهای متن جزئی و نهایی را دریافت کند، خطاها/قطع اتصال را مدیریت کند و با پایان کار نشست را ببندد.
5. ضبط باید با توقف صریح کاربر متوقف شود؛ فایل‌های صوتی نامرتبط گوشی نباید خوانده شوند.

## مرزهای امنیتی
- متن تشخیص‌داده‌شده، حتی اگر با عبارت چالش صوتی برابر باشد، اثبات هویت گوینده یا زنده‌بودن صدا نیست؛ امکان بازپخش/جعل وجود دارد.
- خروجی رونویسی به‌تنهایی مجوز ورود یا اجرای عملیات حساس نیست.
- قفل عملیات حساس و توقف اضطراری `HIC-STOP-01` باید مستقل از مدل حفظ شوند.
- تا وقتی جریان صوتی، مدیریت نشست و آزمون واقعی روی دستگاه پیاده‌سازی نشده‌اند، قابلیت GPT-Live-Transcribe را فعال یا تأییدشده اعلام نکنید.

## وضعیت
این سند مشخصات اجرایی است؛ افزودن آن به مخزن به‌تنهایی اتصال زنده را پیاده‌سازی نمی‌کند. پیاده‌سازی واقعی نیازمند کد جریان صوتی، ایجاد امن نشست سمت سرور، مدیریت رویدادها و آزمون روی دستگاه است.
