# ممیزی شکاف قابلیت‌های هوش مصنوعی هیکتور

این سند وضعیت مشاهده‌شدهٔ شاخهٔ `@Chat-GPT` را از قابلیت‌هایی که هنوز پیاده‌سازی یا روی دستگاه واقعی تأیید نشده‌اند جدا می‌کند. «در کد وجود دارد» به معنی «در همهٔ گوشی‌ها کارکرد آن تأیید شده» نیست.

## افزوده‌شده در این تغییر

- ابزار `search_memory` برای جست‌وجوی محلیِ بدون حساسیت به بزرگی/کوچکی حروف در حافظهٔ هیکتور.
- حداکثر ۲۴۰ نویسه برای عبارت جست‌وجو و حداکثر ۸ خط نتیجه؛ خروجی نیز محدود می‌ماند.
- ابزار از فهرست مجاز و تجزیه‌گر سخت‌گیرانهٔ فراخوانی ابزار عبور می‌کند؛ هیچ دسترسی پوسته، اجرای کد دلخواه یا نوشتن فایل اضافه نشده است.
- آزمون‌های واحد برای تطبیق، ورودی نامعتبر و محدودیت تعداد نتایج افزوده شده‌اند.

## وضعیت قابلیت‌ها

| قابلیت | وضعیت در کد فعلی | محدودیت یا اقدام بعدی |
|---|---|---|
| پاسخ آنلاین از مدل | موجود | نیازمند کلید معتبر، شبکه و مدل در دسترس حساب است |
| جست‌وجوی وب از ابزار مدل | تعریف شده در حلقهٔ Responses API | نتایج و دسترسی وابسته به ارائه‌دهنده و تنظیمات حساب‌اند |
| خواندن حافظهٔ محلی | موجود | خواندن کامل حافظه می‌تواند بیش از حد گسترده باشد؛ جست‌وجوی محدود اکنون افزوده شده |
| جست‌وجوی تاریخچه | موجود | جست‌وجوی متنی ساده است، نه بازیابی معنایی |
| جست‌وجوی حافظه | افزوده‌شده در این شاخه | جست‌وجوی متنی ساده است؛ رتبه‌بندی معنایی هنوز وجود ندارد |
| اجرای چندمرحله‌ای ابزارهای مجاز | موجود با محدودیت تعداد مراحل | تنها ابزارهای مجاز اجرا می‌شوند؛ موفقیت هدف کلی هنوز به‌صورت مستقل اثبات نمی‌شود |
| گزارش نتیجهٔ قابل‌راستی‌آزمایی | زیرساخت موجود | بررسی پس‌شرط‌های واقعی هر هدف باید برای هر ابزار مشخص تعریف شود |
| حافظهٔ رمزگذاری‌شده و همگام‌سازی ابری اختیاری | اجزای مربوط در مخزن موجودند | نیازمند پیکربندی Firebase و آزمون دستگاه واقعی است |
| صدا در پس‌زمینه و اعلان‌ها | اجزای مربوط در مخزن موجودند | نیازمند مجوزهای سیستم، تنظیم سرویس و آزمون روی گوشی هدف است |
| اجرای کاملاً آفلاین با مدل روی گوشی | پیاده‌سازی‌نشده/تأییدنشده | نیازمند انتخاب مدل، بسته‌بندی runtime و سنجش RAM، باتری و سرعت است |
| بازیابی معنایی/برداری حافظه | پیاده‌سازی‌نشده | باید با مجموعهٔ ارزیابی و کنترل حریم خصوصی طراحی شود |
| آزمون خودکار کیفیت پاسخ مدل (مجموعهٔ ارزیابی) | هنوز کامل نیست | نیازمند آزمون‌های ثابت، موارد مرزی فارسی، سنجش صحت و جلوگیری از ادعاهای بی‌مدرک است |
| پیشنهاد اصلاح کد توسط عامل | محدود به ابزارهای فعلی نیست | قبل از ابزار نوشتن کد باید محیط ایزوله، diff قابل‌بازبینی، تست اجباری و تأیید انسان ساخته شود |
| ادغام خودکار تغییرات در شاخهٔ اصلی | عمداً فعال نشده | بدون تأیید انسانی و بررسی CI نباید خودکار شود |
| یادگیری مستقل از تجربه و تغییر خودکار مدل | وجود ندارد | ثبت تاریخچه یا اجرای ممیزی روزانه به معنی یادگیری مدل نیست |
| دسترسی نامحدود به اینترنت، گوشی یا حساب‌ها | وجود ندارد و نباید فرض شود | هر اتصال آینده باید مقصد مشخص، حداقل مجوز، سقف مصرف و تأیید روشن داشته باشد |

## ترتیب پیشنهادی برای توسعه

1. اجرای CI و بررسی این تغییر؛ هیچ قابلیت جدیدی را تا قبولی آزمون‌ها آمادهٔ انتشار فرض نکن.
2. افزودن مجموعهٔ ارزیابی تکرارپذیر برای پاسخ‌های فارسی، ابزارها، خطاهای شبکه و ادعاهای موفقیتِ تأییدنشده.
3. طراحی بازیابی معنایی حافظه با کنترل حذف، محدودیت نگه‌داری و جلوگیری از ارسال غیرضروری داده به سرویس بیرونی.
4. بررسی امکان اجرای مدل محلی روی گوشی هدف، با اندازه‌گیری واقعی مصرف حافظه، باتری و تأخیر.
5. فقط پس از ایجاد محیط ایزوله و تأیید انسانی، بررسی قابلیت پیشنهاد اصلاح کد در شاخهٔ آزمایشی.

## قواعد ایمنی غیرقابل‌تجاوز

- حفظ نبودن ورود با اثر انگشت/زیست‌سنجی در نسخهٔ موردنظر کاربر.
- توقف اضطراری باید همهٔ کارهای جاریِ پشتیبانی‌شده را متوقف کند؛ این کنترل جایگزین قفل سیستم‌عامل نیست.
- خروجی مدل به‌تنهایی مدرک اجرای موفق نیست.
- کلیدهای API، رمزهای امضا و فایل‌های خصوصی نباید وارد مخزن شوند.
- هیچ تغییر پیشنهادی نباید بدون تست و بازبینی، خودکار در نسخهٔ انتشار ادغام شود.
- وضعیت «پیاده‌سازی‌نشده» باید صریح بماند؛ سند نقشهٔ راه یا تست ایستا، اثبات رفتار زمان اجرا نیست.
