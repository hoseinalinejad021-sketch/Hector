# مرحلهٔ اتصال منابع عمومی فرصت درآمد هیکتور

## وضعیت این مرحله
- رجیستری اولیه فقط پیوندهای رسمی فهرست برنامه‌های عمومی HackerOne و Bugcrowd را نگه می‌دارد.
- این رجیستری اتصال زنده، crawler، API client، ارسال گزارش، حساب پژوهشگر یا پرداخت ایجاد نمی‌کند.
- فهرست عمومی به معنی واجد شرایط بودن کاربر، مجاز بودن همهٔ دارایی‌ها یا تضمین پاداش نیست.
- هیکتور در این مرحله هیچ درآمدی کسب نکرده و نباید فرصت یا مبلغ تخمینی را موجودی واقعی نمایش دهد.

## منابع رسمی
- HackerOne: https://hackerone.com/directory/programs
- راهنمای رسمی HackerOne دربارهٔ فهرست برنامه‌ها: https://docs.hackerone.com/en/articles/8410373-directory
- Bugcrowd: https://www.bugcrowd.com/bug-bounty-list/
- راهنمای رسمی Bugcrowd برای یافتن برنامه: https://docs.bugcrowd.com/researchers/participating-in-program/finding-program/

## گام بعدی پیاده‌سازی
1. برای هر منبع بررسی شود آیا API مستند و مجاز برای داده‌های موردنیاز وجود دارد؛ از scraping شکننده یا دورزدن کنترل دسترسی استفاده نشود.
2. اگر API شخصی‌سازی‌شده نیازمند حساب است، اتصال حساب اختیاری و امن باشد و هیچ توکنی در مخزن، گزارش خطا یا لاگ نوشته نشود.
3. برای هر برنامه، URL رسمی، تاریخ آخرین بررسی، وضعیت فعال بودن، محدودهٔ مجاز، شرایط جغرافیایی/KYC، نوع پاداش، حداقل پرداخت، کارمزد و روش برداشت ثبت شود؛ موارد نامعلوم به‌عنوان نامعلوم بمانند.
4. رتبه‌بندی فقط بر اساس داده‌های مستند انجام شود. فرصت کشف‌شده، گزارش پذیرفته‌شده، پاداش تأییدشده و پرداخت واقعی وضعیت‌های جداگانه‌اند.
5. تا قبل از تأیید سیاست هر برنامه، هیچ آزمون امنیتی خودکار، ارسال گزارش یا اقدام مالی انجام نشود.

## معیار پذیرش
- تست رجیستری منابع سبز باشد.
- API یا دادهٔ زنده فقط پس از انتخاب روش دسترسی مجاز اضافه شود.
- خطای شبکه، پاسخ ناقص، منبع منقضی و دادهٔ نامعتبر به‌صورت امن مدیریت شود.
- هیچ فرصت یا درآمد ساختگی به کاربر نمایش داده نشود.
